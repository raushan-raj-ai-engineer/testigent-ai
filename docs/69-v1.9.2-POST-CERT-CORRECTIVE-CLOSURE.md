## Corrective closure

| Finding | Corrective implementation | Regression/acceptance coverage |
| --- | --- | --- |
| R01 — OpenAPI 3.1 schema semantics | Runtime array/object constraints now apply even when a local `type` keyword is omitted. OpenAPI 3.1 null is accepted when no local type restriction rejects it; OpenAPI 3.0 retains nullable behavior. | `maxItems:0`, `maxProperties:0`, unconstrained null, `anyOf(string,null)`, composed constraints, and nullable `$ref` sibling cases through the public response validator. |
| R02 — property-removal compatibility | Compatibility comparison now evaluates the **effective property schema** on both sides: explicit property, `additionalProperties:false`, schema-valued `additionalProperties`, or true/absent. Boolean-schema transitions use exact request-narrowing/response-widening set semantics instead of silently skipping removals. | Optional/required removal cases, false/absent/schema-valued additional-properties policies, request/response direction, and nested objects. |
| R04 — dangling symlink mutation boundary | Project path validation now uses `lstat` before treating a component as absent, so dangling leaf/ancestor links are rejected. Promotion writes re-resolve the path and use exclusive create plus no-follow semantics where supported, preventing a dangling target from being followed. | Direct proposal/mutation resolver counterexample plus real `promoteProposal()` denial; denied promotion creates nothing outside the selected project. |
