# TestigentAI v1.7.0 — Implementation Plan

## Candidate scope delivered in this package

### Phase 1 — Contracts and trust policy

- agent operational states;
- planner/generation/review contracts;
- deterministic trust boundary;
- human approval policy;
- provider-degraded fail-safe semantics;
- project/path governance.

### Phase 2 — Planner and impact intelligence

- deterministic requirement-to-agentic-plan adapter;
- stable plan identity;
- explicit evidence/rationale/confidence;
- UI/API/database/mixed lane mapping;
- deterministic project-scoped change-impact ranking.

### Phase 3 — Proposal-only generator

- governed target-path checks;
- proposal size boundary;
- exact target/content duplicate detection;
- stable proposal identity;
- content digest and requirement/plan provenance;
- no direct project-source mutation.

### Phase 4 — Deterministic reviewer

- architecture/security checks;
- secret/private-key checks;
- authoring-contract checks;
- requirement/assertion checks;
- duplicate/project-boundary checks;
- mandatory review state even after clean deterministic validation.

### Phase 5 — Decision ledger and reporting

- immutable run-scoped decision files;
- central sanitizer reuse;
- conflict detection;
- deterministic summary;
- JSONL convenience export;
- one-click `agentic-intelligence.html`;
- compact dashboard agentic signal.

### Phase 6 — MCP

- stdio JSON-RPC server;
- MCP lifecycle initialize support;
- tools/list and tools/call;
- bounded model-controlled arguments;
- local-only requirement source boundary;
- project/test/impact/planning/review/evidence tools;
- no source mutation or arbitrary execution tools.

### Phase 7 — CI and parity

- blocking `Agentic Deterministic Safety` job in GitHub Actions;
- matching Azure Pipelines deterministic agentic job;
- agentic test suite also included in `validate:final`;
- existing AI deterministic and non-blocking live-provider semantics retained.

### Phase 8 — v1.6.1 certified-fix carry-forward

The package also folds in the certified v1.6.1 canary corrections that were merged after the older R3 package snapshot:

- GitHub step outcome normalization (`success/failure/skipped` -> `passed/failed/skipped`);
- runtime AI canary path initialization through `$GITHUB_ENV`;
- regression coverage proving provider failure becomes valid `DEGRADED` evidence rather than `MISCONFIGURED`/missing evidence.

## Deliberately deferred

The following are not silently enabled in v1.7.0 candidate:

- automatic source promotion;
- autonomous shell/test execution from MCP;
- unrestricted filesystem access;
- autonomous destructive database actions;
- model-controlled secret access;
- automatic acceptance of generated tests;
- an independent second healing engine.

Existing TestigentAI proposal-review/promotion and healing systems remain the authoritative mutation/recovery workflows.
