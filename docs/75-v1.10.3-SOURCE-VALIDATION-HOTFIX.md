# v1.10.3 Requirement Source Validation Hotfix

## Why this release exists

The unified `qa create` workflow previously started auto/manual exploration before validating the supplied requirement source. If a user passed a missing local Markdown path, the browser journey could be completed and approved before the command finally failed with a generic `Unsupported source` message.

## Fixed behavior

`qa create` now validates and loads the requirement **before** any browser exploration starts.

```bash
npm run qa -- create projects/demo/requirements/payment.md --learn="Payment Journey"
```

If the local requirement exists, the CLI prints a validated-source line and only then starts exploration.

If the file is missing, the command fails immediately with a precise message such as:

```text
Requirement file not found: 'projects/demo/requirements/missing.md'.
```

No browser is opened and no unnecessary exploration is performed.

## Demo requirements

The bundled TodoMVC demo now contains a UI-aligned smoke requirement:

```text
projects/demo/requirements/todo-create.md
```

Use this file when validating manual/auto exploration against the demo UI. `payment.md` remains a synthetic multi-layer architecture example and is not intended to represent the TodoMVC browser journey. `projects/demo/requirements/create-order.md` is not bundled; create it only for a project that actually has an order flow.

## Existing captured knowledge

Previously approved application knowledge is not deleted by this change. It can be reused by a later `qa create` invocation using an existing requirement and, where needed, an explicit `--journey=<knowledge-id>`.

## Regression coverage

`tests/framework/requirement-source-validation.contract.spec.ts` protects:

- existing Markdown requirement loading;
- clear missing-file diagnostics; and
- validation-before-exploration ordering in the unified workflow.
