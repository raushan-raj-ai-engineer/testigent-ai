# TestigentAI v1.9.0 — Customer Showcase

## Why the showcase exists

A new customer often opens a dashboard before the repository has accumulated adoption, benchmark, healing, API-contract or failure-history evidence. Blank cards make the product difficult to understand. v1.9.0 therefore includes a realistic demonstration dataset without pretending the examples are real customer results.

## One-click workflow

```bash
npm run showcase
```

The command writes:

```text
reports/showcase/customer-demo/
  index.html
  failure-intelligence.html
  showcase-data.json
```

Open `index.html` to see populated Failure Intelligence, Adoption/Pilot, benchmark, scale-planning, OpenAPI contract, healing and Agentic/MCP examples.

The ordinary business dashboard also contains a `Customer showcase · synthetic` link. That page is rendered from the same isolated dataset and is never inserted into `business-report.json`.

## Trust boundary

Every showcase dataset and scenario must carry:

```json
{
  "mode": "SHOWCASE",
  "synthetic": true,
  "claimEligible": false
}
```

`validateShowcaseDataset()` rejects any attempt to make showcase data claim-eligible. The scale showcase additionally requires `measured=false`, so a synthetic 2,000-case plan cannot appear as real browser-scale certification.

## Included examples

The bundled 10-scenario customer story demonstrates:

1. repeated expired-auth incidents compressed by one stable fingerprint;
2. OpenAPI response contract regression;
3. authenticated application HTTP 500;
4. rejected locator/healing candidate;
5. parallel test-data collision;
6. CI runner resource failure;
7. upstream payment dependency outage;
8. intermittent flaky behavior;
9. fail-honest `UNKNOWN` when evidence is incomplete;
10. cross-application incident/blast-radius visualization.

The numbers are intentionally realistic for explanation, but they are demonstration values only.
