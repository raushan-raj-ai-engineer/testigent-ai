# TestigentAI v1.5.0 — Validation Evidence and Promotion Boundary

Validation date: 13 September 2026.

This document records what was actually verified while closing the v1.4.2 architect/product review. It intentionally separates **verified engineering evidence** from checks that require a connected clean CI runner. A source change is not treated as proof of customer adoption, browser/OS compatibility, or market readiness.

## Verified in the review workspace

- `npm run release:static` passed after the A1–A8 and adjacent hardening changes.
- `npm run release:offline` passed after the same changes.
- A dependency-independent TypeScript parser pass covered the repository TypeScript/TSX sources with zero syntax diagnostics.
- `azure-pipelines.yml`, `.github/workflows/playwright-sharded.yml`, and `.github/workflows/release-compatibility.yml` parsed successfully as YAML.
- Dependency-independent runtime probes passed for:
  - A1 JSON/free-text/URL secret and PII sanitization.
  - A2 explicit external-origin approval.
  - A2 default cross-origin redirect rejection and credential stripping on explicit opt-in.
  - A7 invalid timeout fail-closed behavior.
  - A8 exact-advisory exception matching and unresolved high/critical audit-chain fail-closed behavior.
- Static/review inspection also verified that A3 browser demand, A4 run identity, A5 cache publication, A6 primary-locator readiness, reporting merge identity, shared history locking and evidence-retention controls are wired into the release gate. The connected CI definition now runs `test:review:browser-free` **before** browser installation with `PLAYWRIGHT_BROWSERS_PATH=.runtime/browser-free-proof`, so an accidental browser launch becomes an explicit failure rather than an unobservable dependency.

## Connected clean-CI checks still required before promotion

The review workspace could not complete a clean `npm ci` because registry access stalled, leaving an incomplete dependency tree. Therefore this workspace does **not** claim a completed `tsc --noEmit`, Playwright browser regression run, `npm audit`, or hosted CI matrix run for this candidate.

Promotion requires a connected Node 22 runner to execute:

```bash
npm ci
npm run test:review:browser-free
npx playwright install chromium
npm run validate:final
```

Then run the manual GitHub workflow **TestigentAI Release Compatibility** and retain its uploaded compatibility evidence. The workflow covers the declared Linux Chromium/Firefox/WebKit, macOS WebKit and Windows Chromium matrix and records exact runtime/browser versions.

## No-false-claim rule

Do not convert the checks above into claims of enterprise-wide readiness, false-heal-rate improvement, maintenance savings, 500/2,000-test scale, real database portability, or customer willingness to pay. Those require the pilot and competitive benchmark evidence described in `docs/32-PILOT-ADOPTION-AND-METRICS.md` and `docs/22-COMPETITIVE-BENCHMARK-PLAN.md`.
