## Deep-review corrections made before packaging

The review found and corrected issues that were not allowed into the final candidate:

1. **Empty evidence could look deceptively healthy.** Zero reported scenarios now produce `INSUFFICIENT EVIDENCE`, `UNKNOWN` release risk and `N/A` coverage/pass-rate claims rather than `PROCEED`/`LOW`.
2. **Final CI bundle validation initially did not require the new ledger/graph.** `ci:business:validate` now fails if either file, the truth boundary, run identity or core claim provenance is missing.
3. **Potential graph dangling edges.** Healing/AI/claim edges are only emitted when both endpoints exist in the reported evidence graph.
4. **Attachment links needed a safe boundary.** The ledger links only safe relative report paths; absolute and parent-traversal paths are never rendered as links.
5. **Evidence node insertion was unnecessarily quadratic.** Node identity uses a set, avoiding repeated linear scans as evidence volume grows.
6. **Change-impact analysis re-read test files repeatedly.** Test source text and dependency decisions are cached for the analysis run.
7. **Change-impact heuristic behavior was under-documented.** Conservative feature-ownership hints are now explicitly described as explainable, potentially over-selecting heuristics, never proof that non-selected tests are safe to skip.
8. **Unresolved project changes could return no recommendation.** Any project-owned change with no resolvable mapping now fails safe to all project tests with an explicit reason.
9. **Generic filename words could masquerade as ownership evidence.** Feature-hint extraction now rejects generic framework/support vocabulary and short tokens, so a filename such as `not-mapped.ts` cannot accidentally create a narrow targeted recommendation; it fails safe to the full project suite.
