# TestigentAI v1.6.1 — AI Operational Reliability

## Purpose

v1.6.1 is a focused operational hardening release built on the certified v1.6.0 evidence/release-intelligence baseline. It does **not** change deterministic release facts, false-heal safety, rerun provenance, or the one-click Evidence Ledger.

The goal is to prevent transient third-party AI availability (for example HTTP 503 from Gemini) from being misrepresented as a framework-correctness failure while keeping the outage fully visible and auditable.

## CI separation

### Blocking: AI Deterministic Safety

The `AI Deterministic Safety` job has no external provider dependency. It validates:

- provider selection/failover contracts;
- retry-budget behavior;
- AI runtime audit behavior;
- false-heal safety and semantic post-condition rejection;
- deterministic evaluation contracts.

Failure of this job is a TestigentAI correctness failure and remains release-blocking.

### Non-blocking: AI Live Provider Canary

The `AI Live Provider Canary (non-blocking)` job exercises the configured real provider and the real `@ai` healing journey when enabled. It records one of:

- `HEALTHY` — configuration, generation and live healing passed;
- `DEGRADED` — provider/generation/live healing failed after governed retries;
- `MISCONFIGURED` — provider configuration failed preflight;
- `SKIPPED` — no live provider canary was intentionally run.

A degraded canary emits a GitHub warning and provider-health evidence but does not rewrite deterministic release facts.

## Provider-health evidence

Every canary writes `ai-provider-canary.json` containing only operational metadata: run/attempt identity, provider/model, step outcomes, bounded latency fields and sanitized error class/message. Secrets and prompts are never stored in the provider-health record.

Merge CI resolves the newest canary from the same workflow-run family and appends it to:

```text
.report-history/<app>/<environment>/ai-provider-health.json
```

The store is environment-scoped, lock-protected, atomic and bounded to recent runs.

## Dashboard

The executive dashboard remains compact. `Reliability signals` adds one field:

```text
Live AI provider: HEALTHY | DEGRADED | MISCONFIGURED | SKIPPED
```

`AI provider health ↗` opens `ai-provider-health.html`, which shows:

- latest status;
- recent canary availability percentage;
- sample count;
- average generation latency;
- recent provider/model/outcome history;
- an explicit truth-boundary statement.

Provider-health history is operational evidence only and cannot change the deterministic release decision.

## Rerun behavior

Provider canary artifacts use immutable `run_id-run_attempt` names and are downloaded through the authenticated workflow-run artifact API path. CI selects only same-workflow records at or before the current attempt. Foreign workflow runs are ignored.

Healthy AI business/technical evidence is included in the merged business report only when the **selected immutable canary artifact** completed `HEALTHY`. Merge does not rely on mutable/prior-job outputs to decide AI evidence inclusion. The canary resolver selects the newest valid record from the same workflow-run family at or before the current attempt; an expected-but-missing canary fails closed, while an intentionally skipped canary records `SKIPPED` so historical health cannot masquerade as current health. Degraded canaries remain visible through provider-health evidence instead of contaminating business execution facts.

## Acceptance criteria

Before v1.6.1 can replace v1.6.0 as the certified baseline:

1. `npm run validate:final` passes on supported Node 22;
2. `AI Deterministic Safety` passes on PR and main;
3. a deliberately degraded live-provider canary does not fail the overall workflow and appears as `DEGRADED` in provider-health evidence;
4. a healthy live-provider canary can still contribute AI execution evidence;
5. final business bundle validation requires `ai-provider-health.html`;
6. main rerun provenance remains green;
7. the five-platform/browser Release Compatibility matrix passes.

Until those gates pass, **v1.6.0 remains the certified release baseline**.
