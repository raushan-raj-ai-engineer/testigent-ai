# v1.5.3 — Windows Static-Gate Portability

## Incident

The v1.5.2 release-compatibility matrix passed Ubuntu/Chromium, Ubuntu/Firefox, Ubuntu/WebKit, and macOS/WebKit, but Windows/Chromium failed before browser tests in `npm run release:static` with:

`GitHub merged-report summary must remain informational/non-blocking`

The checked workflow already contained `continue-on-error: true`, `shell: bash`, and the dedicated `ci:business:summary` command. The release checker compared those adjacent YAML lines using an LF-only literal, so Git's Windows CRLF checkout changed the static-check result.

## Correction

- Normalize CRLF/CR to LF before structural workflow/pipeline policy checks.
- Use a whitespace-tolerant reusable matcher for the informational merged-report summary contract.
- Run an explicit portability regression from `npm run release:static` against both LF and simulated CRLF workflow content.
- Keep the original non-blocking summary policy unchanged.

## Acceptance

`npm run release:static` must return the same result for LF and CRLF workflow content. The Windows release-compatibility job must pass `Static and type validation` and proceed to architect-review/recovery regression tests.
