# TestigentAI v1.9.0 — Failure Intelligence

## Purpose

v1.9.0 turns existing execution evidence into deterministic, reviewable triage intelligence. The release does not treat an LLM guess as root-cause truth. It evaluates stable execution signals first, fingerprints equivalent failures, clusters blast radius, and preserves `UNKNOWN` whenever the evidence is insufficient.

## Root-cause taxonomy

The v1.9 deterministic taxonomy is:

- `PRODUCT_DEFECT`
- `AUTOMATION_DEFECT`
- `ENVIRONMENT_FAILURE`
- `TEST_DATA_FAILURE`
- `AUTH_FAILURE`
- `API_CONTRACT_FAILURE`
- `DEPENDENCY_FAILURE`
- `FLAKY_BEHAVIOR`
- `KNOWN_DEFECT`
- `UNKNOWN`

Classification order is evidence-first. Registered defects, authentication state, OpenAPI violations, environment/dependency evidence, test-data evidence and locator/healing evidence take precedence over a generic product-defect guess. An authenticated HTTP 5xx or an authoritative business assertion can become a product-defect classification only when stronger prerequisite failures are absent.

## Stable failure fingerprints

`src/framework/failure-intelligence/failure-fingerprint.ts` removes volatile UUIDs, timestamps, dynamic entity IDs, ports, paths and durations while retaining the business step, normalized endpoint, HTTP status, contract violation and trusted diagnostics. Equivalent failures therefore share a stable SHA-256-derived fingerprint.

The dashboard reports both failed scenarios and unique incidents. Ten failed scenarios may therefore represent fewer than ten triage incidents.

## Historical evidence boundary

`FailureHistoryStore` accepts only non-synthetic, claim-eligible `LIVE` classifications. `SHOWCASE`, synthetic or non-claimable evidence is rejected before it can enter live history. Existing history is immutable for the same fingerprint/scenario identity.

## Optional AI escalation

The deterministic classifier exposes `aiEscalationAllowed=true` only for `UNKNOWN` live evidence. This is an escalation permission, not an automatic truth override. Human confirmation remains recommended for unknown or non-high-confidence outcomes.

## Reporting

Every business dashboard bundle now contains:

- `failure-intelligence.html` — live deterministic failure triage;
- `showcase.html` — isolated synthetic customer showcase;
- `showcase-failure-intelligence.html` — synthetic drill-down with an explicit trust banner.

The normal `business-report.json` is not seeded with showcase records.

## MCP

The governed MCP surface adds two read-only in-memory tools:

- `testigent_explain_failure`
- `testigent_triage_failures`

Neither tool writes project source, promotes generated code or persists synthetic evidence.
