# TestigentAI v1.8.0 — Implementation & Review Closure Plan

## Single-version scope

All remaining high-priority architect-review items targeted for this cycle are consolidated into **one v1.8.0 candidate**. There is no v1.8.1/v1.9 split in this package.

## Priority mapping

| Review priority | v1.8.0 implementation | Acceptance evidence |
| --- | --- | --- |
| Pilot adoption | Immutable adoption observations + portfolio analyzer | 2 applications + 2 opaque engineer aliases before pilot readiness |
| Measured authoring/triage/migration | Adoption metrics + import of existing authoring productivity data | Median/P90/baseline deltas with truth boundary |
| Evidence-based differentiation | Plain-baseline comparative benchmark store/analyzer | Versioned dataset, methodology, raw evidence ref + SHA-256, >=2 apps |
| False-heal safety measurement | Seeded failure evaluator + immutable provenance-backed evidence store/report | Genuine injected business failure can never count as safe recovery; synthetic/incomplete evidence cannot certify |
| 500/2,000 scale proof | Synthetic planner diagnostics + measured scale evaluator | No duplicate/drop, complete execution, bounded imbalance, provenance |
| API contract validation | OpenAPI loader/schema validator | Deterministic response validation + fail-closed status/content type |
| API breaking-change intelligence | Conservative OpenAPI diff | Blocking CLI for supported breaking changes |
| One-click evidence | Three dashboard drill-down pages | Adoption, benchmark/scale and API contract pages |
| CI/release protection | Product Intelligence deterministic suite | GitHub, Azure, `validate:final`, release compatibility matrix |

## Reused architecture

v1.8.0 does not create a parallel framework. It extends:

- `qa` as the primary operator journey;
- `.report-history` for durable evidence history;
- `BusinessDashboardWriter` for drill-down evidence;
- the existing GitHub/Azure deterministic safety topology;
- the existing Release Compatibility browser matrix;
- the existing release static/offline/SBOM/manifest gates.

## Explicitly not added just to increase feature count

The architect review called for pilot-driven prioritization. Therefore this release does **not** claim or introduce a complete accessibility audit platform, load/soak platform, RAG/LLM evaluation suite, hosted multi-tenant RBAC control plane or microservice rewrite. Those remain need-driven roadmap options.

## Review-sensitive controls

- no retries/skips/timeouts added to hide failures;
- agentic and product-intelligence deterministic suites remain browser-neutral so the compatibility matrix selects the browser;
- immutable evidence files use exclusive creation and conflict detection;
- pilot contributor aliases reject PII-like values;
- synthetic benchmark input is explicitly non-certifying;
- example benchmark templates are non-ingestible until copied and completed;
- benchmark claims require source commit and SHA-256 provenance;
- OpenAPI external refs fail closed;
- API breaking CLI can block a release without changing business-test assertions;
- v1.7.0 trust, ledger concurrency and dashboard lifecycle hardening are carried forward.

## Connected certification boundary

The standalone ZIP is a **candidate**. Certification still requires applying it to a clean feature branch from certified v1.7.0 and proving:

1. `npm ci` on Node 22;
2. `npm run validate:final`;
3. deterministic product-intelligence suite under Chromium, Firefox and WebKit selection;
4. PR CI and full rerun;
5. main CI and full rerun after merge;
6. Release Compatibility 5/5;
7. immutable v1.8.0 tag followed by tag-triggered Release Compatibility 5/5.

Measured pilot/scale/competitive claims are separate from release correctness: lack of customer/pilot measurements must display `INSUFFICIENT_EVIDENCE`, not block deterministic framework certification unless the team explicitly makes a benchmark target a release policy.
