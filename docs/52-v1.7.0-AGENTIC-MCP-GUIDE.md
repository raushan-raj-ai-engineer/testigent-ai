# TestigentAI v1.7.0 — Agentic MCP Guide

## Why a second MCP server?

The existing `.mcp.json` Playwright server remains available for Playwright-native tooling. v1.7.0 adds `testigent-agentic`, a TestigentAI-specific MCP boundary that exposes quality-engineering context and deterministic review without giving an external agent unrestricted source mutation.

## Start manually

```bash
npm run mcp:agentic
```

The server communicates over stdin/stdout. stdout is reserved for valid newline-delimited JSON-RPC messages; diagnostics go to stderr.

## `.mcp.json`

The repository registers both:

```text
playwright-test     -> Playwright test MCP server
testigent-agentic   -> governed TestigentAI Agentic Test Intelligence server
```

## Available tools

### `testigent_list_projects`

Lists configured `projects/<app>` folders.

### `testigent_plan_requirement`

Inputs:

- `project`
- `requirementFile`

The requirement must exist under `projects/<project>/requirements`. Remote connector identifiers/URLs are intentionally rejected by the MCP boundary.

### `testigent_analyze_impact`

Inputs:

- `project`
- `changedPaths[]`

Returns deterministic impacted-test candidates with score/reasons.

### `testigent_discover_tests`

Inputs:

- `project`
- optional `query`

Returns project spec paths and discovered tags.

### `testigent_review_generation`

Inputs include:

- project;
- plan id;
- requirement reference;
- artifact kind;
- target path;
- generated content;
- rationale;
- optional confidence/provider/model.

The tool creates an in-memory proposal, runs deterministic review and writes only sanitized decision evidence. It **does not write generated content into project source**.

### `testigent_get_agentic_evidence`

Reads the sanitized run-scoped ledger/summary for the selected project/environment/run.

## Security boundary

The v1.7 MCP server does not expose:

- arbitrary shell commands;
- arbitrary path reads/writes;
- source promotion;
- test execution;
- delete operations;
- credential lookup;
- unrestricted remote requirement retrieval.

This follows the MCP human-in-the-loop principle: model-controlled tools may propose and inspect, while consequential mutations remain governed by explicit TestigentAI workflows.

## Terminal equivalents

```bash
npm run agentic:plan -- projects/demo/requirements/payment.md
npm run agentic:impact -- demo projects/demo/src/pages/payment.page.ts
npm run agentic:review -- ./proposal-input.json
npm run agentic:evidence -- demo <RUN_ID> qa
```

## Evidence and dashboard

Agentic evidence is stored under the selected report run. Regenerating the business dashboard produces:

```text
business/agentic-intelligence.html
```

The business dashboard links to that report while keeping deterministic release facts separate.
