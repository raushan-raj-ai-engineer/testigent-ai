## Additional defects found during remediation

The deep review found and corrected issues that were not separate A1–A8 rows but could otherwise have triggered a follow-up review:

- Merged-report output/history could still fall back to mutable workspace/latest-run state after identity validation. Output now derives from the validated report APP/ENV/RUN identity.
- The first implementation of that merge fallback referenced an undefined local when APP/ENV/RUN_ID were absent. The deep review caught it before packaging; the merge now derives identity from the first validated report and a no-identity-environment regression contract proves the standalone path.
- CI/helper consumers still contained assumptions from the old application-only report layout. They were aligned to run-scoped paths.
- Shared report/duration history was a remaining concurrent mutable state. It is now environment-scoped and lock/atomic-merge protected.
- Cross-origin AI redirects could otherwise forward origin-bound credentials. Redirects are blocked by default; explicit opt-in strips authorization/cookie/API-key headers.
- Provider-returned AI text was an untrusted inbound evidence path. It is sanitized before cache/log/report use.
- A malformed/incomplete high/critical npm-audit dependency chain could otherwise disappear during normalization. It now produces a blocking unresolved advisory.
- `REPORT_HISTORY_FILE` example configuration could reintroduce an unscoped shared history path. The example now documents the scoped default while explicit overrides remain supported.
- Staged validation then exposed that the merge implementation itself had stopped honoring `REPORT_HISTORY_FILE`. Override support was restored and is now asserted by the reporting merge contract.
- Reusable-export comment auditing initially found eight documentation-contract issues introduced by hardening. Those were corrected; the audit now reports 202 declarations and zero issues.
- Node runtime declarations had drifted from release CI. `.nvmrc`, package engines, README/setup and compatibility workflow now consistently target Node 22.x.
- The A3 acceptance proof could be ambiguous on a runner with cached browsers. CI now points Playwright to an intentionally empty browser path and runs the proof before any browser install.

A connected Node 22 runner must execute:

```bash
npm ci
npm run test:review:browser-free
npx playwright install chromium
npm run validate:final
```

Then execute the manual **TestigentAI Release Compatibility** GitHub workflow and retain its evidence artifacts. The browser-free test is intentionally scheduled before browser installation so an accidental UI dependency fails rather than being hidden by runner state.
