# v1.6.0 Pre-Tag CI Hotfix — AI Retry Budget + Failed-Rerun Provenance

Status: **PRE-TAG RELEASE CANDIDATE HARDENING**. This change does not move or create the `v1.6.0` tag. Certification still requires replacement trusted-main CI, a failed-job rerun proof, and the tag-triggered compatibility matrix.

## Why this hotfix exists

Connected certification on Node.js `22.23.2` passed the complete local `npm run validate:final` chain. PR #11 and a full PR rerun also passed. The first trusted-main run then exposed two environment-realistic conditions that local/PR validation could not reproduce:

1. Gemini model/key health succeeded, but `generateContent` returned HTTP `503 UNAVAILABLE` twice. With `AI_TIMEOUT_MS=60000`, `AI_TOTAL_TIMEOUT_MS=90000` and three attempts, early slow failures consumed nearly the entire wall-clock budget and left only ~9.8 seconds for the third attempt.
2. `gh run rerun --failed` does not rerun already-successful independent shard jobs. The rerun merge had `RUN_ID=<run>-2`, while valid core shard artifacts still belonged to `<run>-1`; current-attempt-only download therefore found zero core markers.

These are product hardening defects, not secret/model/authentication defects. Gemini health explicitly confirmed the API key and configured model before generation failed.

## AI retry correction

Gemini retry behavior now:

- keeps the existing overall wall-clock bound;
- distributes remaining request time fairly across the current and future configured attempts;
- reserves future exponential-backoff **and jitter** budget before assigning an attempt timeout;
- retries timeouts by default (`AI_RETRY_ON_TIMEOUT=true`);
- keeps transient HTTP retry status handling (`408`, `429`, `500`, `502`, `503`, `504`);
- continues to fail immediately for permanent 4xx errors;
- validates `AI_RETRY_ON_TIMEOUT` as an explicit boolean string;
- uses `30000ms` as the GitHub CI/default per-attempt timeout while retaining a `90000ms` total budget and three attempts.

A provider that remains unavailable after the bounded retry policy still fails CI. This change improves retry opportunity; it does not turn AI availability failures into passes.

## Failed-job rerun provenance correction

Artifact names remain immutable and attempt-scoped:

```text
<github.run_id>-<github.run_attempt>
```

The merge now downloads only artifact names belonging to the same `github.run_id` family, then `ci:report:rerun:resolve`:

- validates application + environment + workflow run for every marker;
- rejects future attempts and foreign workflow runs;
- resolves each required core shard independently to its newest valid available attempt;
- requires a successful AI lane to come from the **current** attempt;
- selects the technical blob from exactly the same source attempt as its business bundle;
- rejects missing business/blob evidence when a selected marker declares tests;
- writes `_rerun-resolution.json` containing the exact source attempt for every selected lane/shard.

`ci:report:download:validate` requires and cross-checks that resolution manifest whenever prior-attempt reuse is enabled. `merge-business-reports` allows mixed attempt IDs only when they belong to the same explicitly supplied workflow-run family; its published run ID remains the current attempt and aggregation records all source run IDs.

Example legitimate failed-rerun resolution:

```text
core shard 1/2 -> workflow attempt 2
core shard 2/2 -> workflow attempt 1
AI lane       -> workflow attempt 2
```

This is explicit evidence reuse from one immutable commit/workflow run, not a mutable "latest" fallback.

## Regression contracts

The candidate adds/extends contracts for:

- `503 -> 503 -> success` reaching attempt 3;
- timeout retry receiving a fair first-attempt budget rather than consuming the total budget;
- permanent HTTP 400 receiving no retry;
- failed-rerun resolution selecting latest source per core shard;
- current-attempt AI requirement when AI succeeded;
- technical blobs following the same provenance selection as business bundles;
- prior-attempt reuse rejected unless explicitly enabled;
- foreign workflow-run artifacts rejected;
- business merge exposing both prior/current source attempt IDs while publishing the current attempt identity.

## Release acceptance after applying this candidate

Run locally on Node 22:

```bash
rm -rf node_modules
npm ci
npx playwright install chromium
npm run validate:final
```

Then require:

1. feature PR CI green;
2. PR rerun green;
3. trusted-main CI with AI lane green;
4. `gh run rerun <main-run-id> --failed` or a controlled failing/recovery proof demonstrating rerun provenance;
5. `v1.6.0` tag only after main is green;
6. Ubuntu Chromium/Firefox/WebKit, macOS WebKit and Windows Chromium compatibility all green.

Until those pass, `v1.5.3` remains the certified baseline.
