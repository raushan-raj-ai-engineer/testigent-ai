# TestigentAI v1.6.1 — Deep Review and Validation Record

## Release intent

v1.6.1 is an operational-reliability candidate built on the immutable certified v1.6.0 baseline. It deliberately avoids changing deterministic release-risk, false-heal, evidence-graph, change-impact or rerun-provenance semantics.

Its scope is limited to separating deterministic AI correctness from live third-party provider availability and making live provider health visible in the existing evidence/reporting experience without adding dashboard complexity.

## Review findings closed before packaging

1. **Provider outage vs framework correctness** — deterministic/provider-neutral AI contracts are blocking; the real provider/healing journey is an operational canary.
2. **Provider health truth boundary** — live health is rendered separately and explicitly cannot rewrite deterministic business outcomes or release facts.
3. **Rerun-safe canary identity** — merge selects the newest canary from the same workflow run at or before the current attempt.
4. **Artifact-driven AI evidence inclusion** — merge uses the selected canary artifact, not a previous job output, to decide whether live AI business evidence is eligible.
5. **Missing expected canary** — fails closed with `AI_PROVIDER_CANARY_MISSING`.
6. **Intentional skip** — records `SKIPPED` for the current run so stale historical provider health cannot look current.
7. **Provider-health persistence** — environment-scoped, bounded, lock-protected and atomically written.
8. **One-click evidence** — the compact business dashboard links to `ai-provider-health.html` rather than embedding a large operational table.
9. **GitHub/Azure parity** — both CI systems implement a blocking deterministic AI safety lane and a non-blocking live-provider canary.
10. **Healthy-only business evidence** — live AI technical/business/audit artifacts are published/merged only for a healthy canary; degraded operational evidence remains separate.

## Certification boundary

The packaging environment does not replace the connected release gates. v1.6.1 must **not** be described as certified until all of the following pass from the final candidate on supported Node 22:

1. `npm ci`;
2. `npm run validate:final`;
3. PR CI with blocking `AI Deterministic Safety` green;
4. PR rerun with report/provenance green;
5. main CI with deterministic AI safety green and live canary truthfully reported;
6. main rerun proving provider-health/rerun behavior;
7. tag-triggered five-platform/browser Release Compatibility matrix.

A `DEGRADED` live provider canary is not itself a deterministic TestigentAI correctness failure. However, canary evidence must be generated, ingested and surfaced truthfully; missing expected canary evidence remains release/merge blocking.

Until these connected gates complete, **v1.6.0 remains the certified baseline**.
