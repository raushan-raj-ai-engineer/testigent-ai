# TestigentAI v1.5.1 — Runtime Contract Closure

> **Historical release evidence.** This document records the release state at that version. The current certified baseline is **v1.6.0**; use `41-CURRENT-RELEASE-STATUS.md`, `33-RELEASE-COMPATIBILITY-MATRIX.md`, and `40-GIT-GITHUB-CLI-TERMINAL-GUIDE.md` for current operations.

## Trigger

A real connected Node 22 / Chromium `npm run validate:final` execution reached `test:review:hardening` after release/static, architecture, framework health, scale, scenario, documentation, reporting and TypeScript checks had passed. Nine healing-generation tests then failed with the same root cause: the new locator-readiness diagnostic path called `logger.debug()` on lightweight injected loggers that only implemented `warn()`.

## Root cause

The healing orchestrator was typed against the concrete `EnterpriseLogger`, while several contract tests intentionally used minimal logger doubles and bypassed the mismatch with `as any`. The readiness-window hardening introduced the first `debug()` call in that path, turning the hidden contract mismatch into a runtime failure.

## Correction

- `HealingOrchestrator` now depends on a minimal logger contract: `warn()` required, `debug()` optional.
- Readiness-miss debug output is best-effort and cannot change healing control flow if the method is absent or diagnostic logging throws.
- The AI collaborator is narrowed to `Pick<AiGateway, 'proposeLocator'>` rather than the concrete gateway class.
- `BaseApiClient` similarly depends only on the `info()` logger method it consumes.
- Generic `ProjectPaths` no longer consults `.runtime/latest-run` implicitly. Read/write paths use only an explicit run ID or the current process `RUN_ID`; user-facing report commands opt into the latest pointer explicitly.
- Logger `as any` casts were removed from the healing/review hardening tests.
- A dedicated regression uses a logger with `warn()` only and requires deterministic fallback to succeed.

## Promotion gate

Run on the connected release workstation/CI with Node 22 and installed Playwright Chromium:

```bash
npm ci
npx playwright install chromium
npm run validate:final
```

Promotion requires the entire command to pass. In particular, `test:review:hardening` must include the partial-logger regression and all healing generation contracts with zero failures.

## Review posture

This patch does not weaken or bypass any A1–A8 architect-review control. It removes a test-double/type-contract blind spot so future collaborator-contract changes fail earlier and more explicitly.
