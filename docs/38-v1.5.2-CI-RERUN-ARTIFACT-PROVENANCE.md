# TestigentAI v1.5.2 — CI Rerun Artifact Provenance

## Failure reproduced

A GitHub Actions rerun used `RUN_ID=<github.run_id>-2` while intermediate artifact names remained attempt-agnostic (`business-<app>-core-1`, `business-<app>-core-2`, etc.). The final merge correctly failed closed with `expected 2 ... found 0` rather than publishing an incomplete business report.

## Root cause

GitHub workflow reruns reuse the same workflow run while incrementing `github.run_attempt`. Artifact names that omit the attempt identity are therefore not a sufficient provenance boundary. TestigentAI already scoped report content by `RUN_ID`, but the GitHub artifact transport layer did not carry the same identity.

## Correction

GitHub CI now uses attempt-scoped names:

- `blob-<app>-<RUN_ID>-core-<shard>`
- `business-<app>-<RUN_ID>-core-<shard>`
- `blob-<app>-<RUN_ID>-ai`
- `business-<app>-<RUN_ID>-ai`
- `ai-audit-<app>-<RUN_ID>`
- `testigent-ai-report-<app>-<RUN_ID>`

Merge downloads use the same current-attempt patterns. Cleanup deletes only matching current-attempt intermediates.

## Additional reliability controls

- Core/AI business uploads fail if their expected directory is absent.
- The merge job lists downloaded bundle files and verifies marker count before aggregation.
- `EXPECT_AI_LANE=true` only when the AI job result is `success`.
- Static release validation asserts the rerun-safe artifact contract.

## Acceptance

A normal run and a rerun of failed jobs must both produce a complete merged report for their own `RUN_ID`. No report or marker from another attempt may satisfy the current attempt's topology gate.

## CI maintenance

The report-history cache uses `actions/cache@v6` to avoid the deprecated Node 20 action runtime on current GitHub-hosted runners. The release compatibility matrix remains manually dispatchable and also runs automatically for `v*` release tags. Self-hosted GitHub runners must satisfy the action's supported runner-version requirement before adopting this release.
