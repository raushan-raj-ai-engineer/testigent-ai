# TestigentAI v1.8.0 — API Contract Intelligence

## Purpose

Service-heavy teams need deterministic API compatibility evidence in addition to UI/API functional assertions. v1.8.0 adds an OpenAPI 3 contract layer without changing project ownership: product OpenAPI documents remain project/team assets while reusable validation and compatibility logic lives in `src/framework/api-contract/`.

## Capabilities

### OpenAPI loading

- JSON and YAML OpenAPI 3.x documents;
- local `#/components/schemas/...` references;
- unresolved or external schema references fail closed instead of being silently ignored.

### Response contract validation

The deterministic validator supports the common schema subset used by service tests:

- object, array, string, number, integer, boolean and null;
- `required`;
- nested `properties` and `items`;
- `enum`;
- `nullable`;
- `oneOf`, `anyOf`, `allOf`;
- `additionalProperties`.

Undeclared HTTP status codes fail. When an actual response content type is supplied, an undeclared content type also fails; it is not silently treated as JSON.

### Breaking-change detection

The conservative compatibility detector identifies:

- removed paths;
- removed methods;
- removed responses;
- removed response/request content types;
- request body becoming required;
- new required request properties;
- previously guaranteed response properties becoming optional;
- schema type changes;
- request enum values removed;
- new response enum values that existing consumers may not understand.

This is intentionally a deterministic OpenAPI subset, not a claim of full OpenAPI/JSON-Schema semantic equivalence.

## Commands

```bash
npm run api:contract:summary -- \
  --spec=benchmarks/examples/openapi-baseline.yaml

npm run api:contract:validate -- \
  --spec=benchmarks/examples/openapi-baseline.yaml \
  --method=GET \
  --path='/users/{id}' \
  --status=200 \
  --body=benchmarks/examples/response-user.json \
  --content-type=application/json

npm run api:contract:diff -- \
  --baseline=benchmarks/examples/openapi-baseline.yaml \
  --current=benchmarks/examples/openapi-breaking.yaml

npm run api:contract:breaking -- \
  --baseline=api/openapi-main.yaml \
  --current=api/openapi-candidate.yaml
```

`api:contract:breaking` exits non-zero when breaking changes are detected and is suitable for an explicit service contract gate.

## Evidence

Run-scoped output is written under:

```text
reports/<application>/<environment>/<run-id>/api-contract/
  api-contract-summary.json
  api-contract-summary.md
  api-contract-intelligence.html
```

The main business dashboard exposes `api-contract-intelligence.html` but API contract results do not rewrite deterministic business-test facts.
