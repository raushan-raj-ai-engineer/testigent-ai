# v1.10.1 Complex Exploration & Requirement-Driven Generation

## User entry paths

The selected project can create automation evidence in four ways while using one review/promotion model:

1. **Safe Auto Explore** — discover routes, forms, tables/grids, dialogs/iframes/canvas metadata and observed XHR/fetch traffic without intentionally executing destructive controls.
2. **Manual Guided Learn** — a tester performs the real business journey in a headed browser while TestigentAI captures semantic interactions and network evidence.
3. **Markdown requirement** — generate from a project `.md` requirement plus approved exploration knowledge.
4. **Jira ticket** — use `JIRA:PAY-142` or a Jira `/browse/PAY-142` URL. Jira summary, description, labels, priority, components, configured acceptance-criteria field and manual-steps field normalize into the same `RequirementDocument` used by Markdown.

## Setup

```bash
npm ci
npx playwright install chromium
npm run qa:use -- demo qa
```

For exploration:

```bash
APPLICATION_EXPLORATION_ENABLED=true npm run qa -- explore
APPLICATION_EXPLORATION_ENABLED=true npm run qa -- learn "Create Order Journey"
```

Cross-origin frames must be explicitly allowed:

```bash
EXPLORATION_ALLOWED_ORIGINS=https://payments.example.test,https://identity.example.test
```

## Complex UI capture

Guided learning captures semantic locator candidates and component context for:

- HTML tables and ARIA grids
- AG Grid, MUI DataGrid, PrimeNG, Kendo Grid, DevExtreme
- stable row key / visible row context / virtualization signals
- same-origin and explicitly allowed cross-origin nested iframes
- open Shadow DOM host metadata
- dialogs/modals and browser-native dialog events
- popups/new tabs and downloads
- file upload semantics without persisting local filenames as credentials
- keyboard interactions and shortcuts
- native and pointer-inferred drag/drop
- hover
- scroll / near-bottom infinite-scroll signals
- canvas click coordinates
- XHR/fetch observations correlated to nearby UI actions

Typed field values are **not recorded**. The generated journey data deliberately contains `REVIEW_AND_SET_VALUE` / `REVIEW_AND_SET_FILE_PATH` placeholders until a human provides approved test data.

## Generate from Jira

Configure one Jira authentication mode:

```bash
JIRA_BASE_URL=https://company.atlassian.net
JIRA_EMAIL=user@company.com
JIRA_API_TOKEN=...
# OR JIRA_BEARER_TOKEN=...
```

Optional Jira custom fields:

```bash
JIRA_ACCEPTANCE_CRITERIA_FIELD_ID=customfield_12345
JIRA_MANUAL_STEPS_FIELD_ID=customfield_12346
```

Then either form works:

```bash
npm run qa -- generate JIRA:PAY-142 --journey=payment
npm run qa -- generate https://company.atlassian.net/browse/PAY-142 --journey=payment
```

## Staged proposal, review, approval, promotion

Generated files are staged under:

```text
.testigent/proposals/<requirement>/workspace/
```

They are **not** written into the project immediately.

```bash
npm run qa -- proposal validate PAY-142
npm run qa -- proposal approve PAY-142 --reviewer="QA Lead"
npm run qa -- proposal promote PAY-142
```

Validation blocks unresolved test-data placeholders, TypeScript syntax errors and credential-like literals. Approval stores immutable file hashes. Promotion refuses if a staged file changed after approval, if a destination changed since generation, or if promotion would overwrite a pre-existing target.

## Dynamic grid example

A manually selected row is generated as reusable data-driven semantics rather than an nth-child selector:

```ts
const row = root.getByRole('row').filter({ hasText: data.rowKey });
await row.getByRole('button', { name: 'Edit' }).click();
```

## iframe example

```ts
let root: Page | FrameLocator = this.page;
root = root.frameLocator('iframe[title="Secure payment"]');
await root.getByRole('button', { name: 'Pay' }).click();
```

## Limits / truth boundary

Closed Shadow DOM cannot be generically inspected by browser automation. Canvas applications may require application-specific accessibility/test hooks for semantic actions beyond coordinates. Auto-explore intentionally avoids destructive controls; use manual guided learning in a safe QA environment for destructive-looking business flows such as payment/order submission.
