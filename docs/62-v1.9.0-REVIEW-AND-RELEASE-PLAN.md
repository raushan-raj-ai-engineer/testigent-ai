# TestigentAI v1.9.0 — Review & Release Plan

## Release intent

v1.9.0 is one consolidated candidate containing Failure Intelligence, customer showcase data, read-only MCP triage and the final reporting-surface freeze. It is not split into a follow-up reporting release.

## Review priorities

The candidate must prove:

1. failure classification remains deterministic and evidence-first;
2. volatile identifiers do not fragment one failure into many incidents;
3. `UNKNOWN` is retained when evidence is incomplete;
4. synthetic/showcase evidence can never enter live claim/history paths;
5. dashboard showcase pages remain visibly labeled and separate from live facts;
6. read-only MCP triage cannot write/promote source;
7. npm security audit remains fail-closed if the legacy quick-audit endpoint is unavailable;
8. reporting surface is frozen after v1.9 except governed corrective changes;
9. all v1.8 product-intelligence, v1.7 agentic and earlier framework contracts remain green.

## Mandatory candidate gates

```bash
npm ci
npm run typecheck
npm run showcase:validate
npm run test:failure-intelligence
npm run test:product-intelligence
npm run test:agentic:deterministic
npm run test:review:hardening
npm run test:framework:critical
npm run security:check
npm run release:static
npm run validate:final
```

Connected certification still requires PR CI + rerun, main CI + rerun, Release Compatibility 5/5, exact SHA agreement, annotated tag, and tag-triggered Release Compatibility 5/5.

## No review-comment guarantee

No release process can guarantee that an independent reviewer will have zero comments. The design instead removes predictable review findings by enforcing explicit trust boundaries, deterministic contracts, isolated demo data, immutable evidence, browser-neutral safety tests and fail-closed security behavior.
