# v1.6.0 Pre-Tag Rerun Artifact Acquisition Closure

Status: **PRE-TAG RELEASE CANDIDATE HARDENING**. This closes the remaining GitHub partial-rerun acquisition gap discovered after the v1.6.0 R3 provenance resolver was merged. It does not create or move the `v1.6.0` tag.

## Observed trusted-main behavior

Main CI proved that the R3 resolver and merged reporting path worked on a normal attempt, while Gemini retry hardening reached all configured attempts. A later `gh run rerun <run-id> --failed` produced a second workflow attempt in which the AI lane passed, but `Resolve rerun-safe report provenance` failed with:

```text
Rerun artifact resolution is incomplete: no core shard 1/2 exists for workflow run 34758076354.
```

The resolver was correctly fail-closed. The missing evidence was an **artifact acquisition** problem: `actions/download-artifact` without an explicit GitHub token/run identifier uses the current-run backend context. A partial rerun can therefore expose only artifacts visible to the current attempt even though immutable evidence exists elsewhere in the same workflow-run family.

## Acquisition correction

The merge job now downloads technical and business artifacts with all of the following inputs:

```yaml
github-token: ${{ github.token }}
repository: ${{ github.repository }}
run-id: ${{ github.run_id }}
```

Supplying those inputs makes artifact lookup use the authenticated workflow-run/public API path instead of relying on the current-attempt backend view. The existing artifact-name pattern remains restricted to the same `github.run_id` family, after which `ci:report:rerun:resolve` still performs application/environment/run/attempt/shard validation before any evidence is accepted.

This does **not** weaken provenance rules. The resolver still rejects:

- foreign workflow runs;
- future attempts;
- wrong application/environment;
- missing or duplicate required shards;
- stale AI evidence when the current AI lane succeeded;
- business/technical source-attempt mismatches.

## Evidence-retention correction

A second failure mode was identified during the same review. The merge job previously removed intermediate shard artifacts whenever merged reporting itself succeeded, even if another required execution lane had failed and caused the overall workflow to fail. That could destroy the exact evidence a later failed-only rerun needed.

Intermediate cleanup now requires all of the following and, once those conditions are met, removes intermediate artifacts across the complete `github.run_id` attempt family rather than only the latest attempt:

```text
business merge success
final business validation success
final artifact upload success
core test job success
AI job success OR AI intentionally skipped
not a pull request
```

If a required core or AI lane fails, intermediate artifacts are retained for diagnosis and safe rerun resolution. The AI-audit download uses the same authenticated workflow-run lookup as technical/business evidence.

## Regression protection

`ci-rerun-artifact-contract.ts` now checks the workflow acquisition/retention contract in addition to synthetic provenance selection. `release:static` also fails if either of these controls disappears:

1. workflow-run artifact downloads must carry `github-token`, `repository`, and `run-id`;
2. cleanup must be guarded by successful required execution lanes.

The existing synthetic contract continues to prove mixed-attempt selection such as:

```text
core shard 1 -> attempt 2
core shard 2 -> attempt 1
AI lane      -> attempt 2
```

while rejecting foreign workflow-run artifacts.

## Release acceptance

After applying this closure candidate:

1. run `npm run validate:final` on Node 22;
2. require PR CI green;
3. rerun the PR workflow and require the merge/provenance step green;
4. merge to `main` and require the AI lane + core lanes + merged reporting green;
5. rerun the trusted-main workflow and confirm workflow-run artifact acquisition resolves every required lane/shard;
6. only then create `v1.6.0`;
7. require the five-platform/browser Release Compatibility matrix to pass.

Until these connected gates pass, `v1.5.3` remains the certified baseline.
