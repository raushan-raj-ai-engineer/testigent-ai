# TestigentAI v1.7.0 — Agentic Test Intelligence

## Status

Architecture Candidate

## Certified Baseline

TestigentAI v1.6.1 remains the certified baseline.

v1.7.0 development must not modify or move the v1.6.1 release tag.

## Objective

Introduce controlled agentic testing capabilities while preserving deterministic
release correctness, evidence provenance, security boundaries, multi-project
architecture, and provider-independent framework operation.

## Core Principles

1. AI proposes; deterministic policy decides.
2. Agentic actions must be explainable and auditable.
3. Missing evidence must fail closed.
4. Provider availability must not redefine release correctness.
5. Project-specific logic must remain outside reusable framework core.
6. MCP must expose controlled capabilities rather than unrestricted framework access.
7. Generated or healed tests cannot become trusted evidence without validation.
8. Existing non-AI execution must continue when agentic capabilities are disabled.

## Agentic Flow

Requirement / Change
→ Planner
→ Impact Analysis
→ Generator
→ Deterministic Reviewer
→ Controlled Execution
→ Healer
→ Post-condition Validation
→ Evidence
→ Reporting

## Components

### Planner

Produces structured test plans from requirements or change context.

The planner must provide:

- affected project
- affected requirement
- impacted scenarios
- recommended test lanes
- rationale
- confidence
- evidence references

### Generator

Produces framework-compliant test proposals.

Generation must:

- reuse existing framework abstractions
- avoid duplicate test creation
- preserve requirement traceability
- respect project boundaries
- remain reviewable before trust

### Reviewer

Evaluates agent-produced artifacts before they are considered valid framework assets.

The reviewer must detect:

- architecture violations
- raw framework bypasses
- unsafe external calls
- secrets or sensitive data
- unsupported selectors/endpoints
- missing traceability
- missing deterministic assertions

### Healer

Existing safe healing remains separate from generation.

Healing must continue to require:

- bounded candidates
- evidence
- post-condition verification
- false-heal protection
- auditability

### MCP

MCP exposes controlled TestigentAI capabilities to external assistants and agents.

Initial MCP capabilities should be read-oriented:

- test planning
- impact analysis
- test discovery
- requirement discovery
- evidence lookup

Mutation and execution tools require explicit policy controls.

## Agent Decision Ledger

Every meaningful agentic operation must record:

- agent
- operation
- input references
- decision
- rationale
- confidence
- policy result
- provider/model when applicable
- evidence
- affected artifacts
- workflow run
- timestamp

## Operational States

Agentic operations must support explicit states such as:

- ACCEPTED
- REJECTED
- REVIEW_REQUIRED
- INSUFFICIENT_EVIDENCE
- SKIPPED
- DEGRADED

UNKNOWN conditions must not be presented as successful decisions.

## Reporting

The business dashboard should expose a compact Agentic Intelligence summary.

Detailed evidence should be available through a one-click agentic intelligence report.

## Fail-safe Requirements

AI unavailable:
deterministic framework continues.

MCP unavailable:
normal TestigentAI execution continues.

Planner uncertainty:
REVIEW_REQUIRED.

Generator uncertainty:
proposal only.

Reviewer failure:
generated artifact cannot become trusted evidence.

Missing provenance:
fail closed.

Provider degradation:
record operational degradation without rewriting deterministic release facts.

## Multi-project Requirement

Reusable agentic capabilities belong in src/framework.

Project-specific configuration, requirements, pages, tests, data, and domain knowledge
remain in projects/<app>.

No reusable agent should contain demo-specific or sdet-practice-specific behavior.
