# TestigentAI v1.7.0 — Agentic Test Intelligence

## Status

**Development candidate.** TestigentAI v1.6.1 remains the immutable certified baseline.

## Objective

Introduce controlled agentic testing capabilities while preserving deterministic release correctness, evidence provenance, security boundaries, multi-project architecture, and provider-independent framework operation.

## Core principles

1. AI proposes; deterministic policy decides.
2. Agentic actions must be explainable and auditable.
3. Missing evidence fails closed.
4. Provider availability must not redefine release correctness.
5. Project-specific logic remains outside reusable framework core.
6. MCP exposes controlled capabilities rather than unrestricted filesystem or execution access.
7. Generated or healed tests cannot become trusted evidence without deterministic validation and required human approval.
8. Existing non-AI execution continues when agentic capabilities are disabled or unavailable.

## Agentic flow

```text
Requirement / Change
        ↓
Planner
        ↓
Impact Analysis
        ↓
Generator (proposal only)
        ↓
Deterministic Reviewer
        ↓
Trust Policy / Human Approval
        ↓
Controlled Existing Promotion Workflow
        ↓
Execution / Healing
        ↓
Evidence / Reporting
```

## Planner

The planner reuses existing requirement intelligence rather than creating a second requirement engine. It adds:

- stable plan identity;
- explicit operational state;
- confidence and rationale;
- requirement/source evidence;
- UI/API/database/mixed lane classification;
- fail-closed behavior for missing/conflicting evidence;
- deterministic change-impact ranking.

The planner does not write test source.

## Generator

The v1.7 generator boundary creates an in-memory generation proposal. It validates:

- selected project boundary;
- target path/file type;
- proposal size;
- exact target/content duplication;
- requirement and plan provenance.

It never writes generated code directly into `projects/<app>`.

## Reviewer

The deterministic reviewer checks generated proposals for:

- hard-coded credentials/private keys;
- absolute environment URLs;
- raw Playwright UI bypasses in generated tests;
- direct healer/AI/API infrastructure construction;
- direct runtime/database environment reads;
- missing requirement tags;
- missing deterministic assertions;
- duplicate generation and project-boundary violations.

Passing deterministic review still produces `REVIEW_REQUIRED` when human approval is required.

## Trust policy

The trust boundary supports:

- `ACCEPTED`
- `REJECTED`
- `REVIEW_REQUIRED`
- `INSUFFICIENT_EVIDENCE`
- `SKIPPED`
- `DEGRADED`

Only `ACCEPTED` may become trusted evidence. Provider degradation, missing provenance, policy violations, failed deterministic validation, low/missing required confidence, or missing required human approval cannot cross the trust boundary.

## Agent decision ledger

Meaningful agentic decisions are stored as immutable run-scoped JSON records under:

```text
reports/<app>/<env>/<runId>/agentic/decisions/
```

A regenerated convenience view is written to:

```text
reports/<app>/<env>/<runId>/agentic/agent-decision-ledger.jsonl
```

Persisted evidence is passed through the central TestigentAI secret/PII sanitizer. Conflicting reuse of the same decision id fails closed.

## MCP boundary

The governed MCP server uses newline-delimited stdio JSON-RPC and the stable MCP `2025-06-18` protocol contract. It exposes tools for:

- project discovery;
- local project requirement planning;
- deterministic change-impact analysis;
- test discovery;
- proposal-only generation review;
- run-scoped agentic evidence lookup.

The server intentionally does **not** expose source promotion, arbitrary file write/delete, shell execution, test execution, secret retrieval, or unrestricted remote requirement access.

## Reporting

Every generated business dashboard bundle includes:

```text
agentic-intelligence.html
```

The main dashboard shows compact agentic decision count/state and links to the decision ledger drill-down. Agentic status is informational/governance evidence; it does not overwrite deterministic business test outcomes or release facts.

## Fail-safe behavior

```text
AI unavailable              -> deterministic framework continues
MCP unavailable             -> normal CLI/tests continue
planner uncertainty         -> REVIEW_REQUIRED / INSUFFICIENT_EVIDENCE
generator uncertainty       -> proposal only
review failure              -> REJECTED; no promotion
missing provenance          -> fail closed
human approval required     -> REVIEW_REQUIRED until approved
provider degradation        -> DEGRADED; deterministic release facts unchanged
```

## Multi-project boundary

Reusable agentic capability lives in `src/framework/agentic` and `src/framework/mcp`. Product requirements, pages, workflows, APIs, repositories, data and business specs remain under `projects/<app>`.

The reusable layer must never import a product project or encode demo/sdet-practice domain behavior.

## Release gate

v1.7.0 cannot become certified until:

- deterministic agentic contract tests pass;
- MCP security/protocol tests pass;
- provider-disabled framework execution passes;
- multi-project isolation passes;
- evidence/provenance validation passes;
- dashboard/final bundle validation passes;
- GitHub and Azure CI agentic gates pass;
- main + rerun behavior is stable;
- Release Compatibility matrix passes on Ubuntu Chromium/Firefox/WebKit, macOS WebKit and Windows Chromium.
